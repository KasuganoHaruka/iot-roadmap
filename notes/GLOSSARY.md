# 术语表

看讲义时遇到不认识的词，回这里查。每条只讲**它是什么**和**为什么你会碰到它**，
不展开——展开在对应那一周的讲义里。

---

## 电气与物理层（W1）

### 差分信号
用**两根线的电压差**表示 0 和 1，而不是"一根线相对地的电压"。干扰会同时加在两根线上，相减就抵消了。**RS-485 能跑 1200 米而 RS-232 只能跑 15 米，全靠这个。**

### 共模干扰 / 共模抑制
"共模"指**同时、等量**加在两根信号线上的干扰。差分接收只看两线之差，所以共模干扰被自动消掉——这个能力叫共模抑制。

### 共模电压范围
收发器能容忍的两台设备**地电位差**的范围，典型 −7V ~ +12V。超出这个范围，即使差分信号本身没问题，芯片也判不出电平。长距离或跨配电箱时要用**隔离型**收发器。

### 终端电阻（120Ω）
装在总线**物理两端**的电阻，用来吸收信号在线路末端的反射。**只能装两个**；装三个会让总阻抗降到 40Ω，驱动器带不动，表现为**随机丢包**——最难查的那种故障。

### 地环流
屏蔽层两端都接地时，因两端地电位不同而在屏蔽层上流过的电流，反而把干扰引进来。**所以屏蔽层只接一端。**

### 菊花链（手拉手）
485 总线唯一正确的拓扑：设备一台接一台串成一条线。**不能星型、不能拉长支线**——那等于制造额外的信号反射点。

### A/B 极性
RS-485 的两根信号线。不同厂家标法不一：A/B、D+/D−、485+/485−。一般 A = D+ = 485+。**接反了不烧，但收不到数据。**

### 分包 / 粘包
串口和 TCP 都是**字节流，没有消息边界**。一帧数据可能分几次到达（分包），两帧也可能挤在一次读取里（粘包）。**必须自己分帧**，不能假设"读一次 = 收到一帧"。

## Modbus（W2–W4）

### PDU（协议数据单元）
一帧报文里**功能码 + 数据**的那一段，不含从站地址和校验。RTU 和 TCP 的 PDU **完全一样**，差别只在外面的壳——这就是驱动能共用一套编解码的原因。

### MBAP 头
Modbus **TCP** 特有的 7 字节头：事务ID(2) + 协议ID(2，恒为0) + 长度(2) + 单元ID(1)。**全部大端**。RTU 没有它，改用从站地址 + CRC。

### 功能码
告诉从站"要做什么"的一个字节。常用：**03** 读保持寄存器、**04** 读输入寄存器、**06** 写单个寄存器、**10** 写多个寄存器。

### 保持寄存器 / 输入寄存器 / 线圈 / 离散输入
Modbus 的四个数据区。**寄存器是 16 位的"字"，线圈是 1 位的"开关"**；保持寄存器和线圈可读可写，输入寄存器和离散输入只读。

### 4xxxx 记法
传统 PLC 文档里的地址写法（`40001` 表示第 1 个保持寄存器），是 **1 开始**的；而协议报文里的地址是 **0 开始**的。**文档写 40001，报文填 0**——这是"数据整体错位一格"的头号原因。

### CRC16
Modbus RTU 的校验码。参数：多项式 `0xA001`、初值 `0xFFFF`。**传输时低字节在前**（而数据域是大端）——这个不一致是规范的历史遗留，记住即可。自检向量：`"123456789"` → `0x4B37`。

### 字序（Word Order）
两个 16 位寄存器拼成一个 32 位数时，谁在前、字节怎么排。四种：**ABCD**（标准大端）、**CDAB**（字交换，最常见的"非标"）、BADC、DCBA。**32 位浮点读出来是乱码，99% 是字序错。**

### 异常响应
从站出错时返回**功能码 + 0x80**，后跟一个字节异常码。最常见的是 **02 = 非法数据地址**（地址越界，或 4xxxx 没减 1）。**异常码不该重试，超时才该重试。**

### 批量读优化
把离散的地址合并成尽量少的请求。两个约束：合并后跨度 ≤ 125 个寄存器；中间的"空洞"不能太大（多读的也要花时间）。**这是 Modbus 相关面试题里最能拉开差距的一个。**

### 熔断（Circuit Breaker）
某台设备连续失败几次后，**暂时不再向它发请求**，隔一段时间再试一次。防止一台掉线的设备每轮都占用总线时间，拖垮其他设备。

### 指数退避
重试间隔一次比一次长：1s → 2s → 4s → 8s → 30s 封顶。再加随机抖动，避免多台设备同时重连造成拥塞。

## Linux 与部署（W5）

### systemd unit
Linux 上描述"一个服务怎么启动、崩了怎么办"的配置文件。关键项：`Restart=always`（崩了自动拉起）、`StartLimitBurst`（防止崩溃循环把日志刷爆）。

### udev 规则
把设备文件名固定下来的机制。**两个 USB 转 485 插上去，重启后 `/dev/ttyUSB0` 和 `ttyUSB1` 可能对调**——用 udev 按硬件序列号绑定成 `/dev/ttyModbus0`，就不会错。

### self-contained 发布
把 .NET 运行时一起打包进去，**目标机器不需要预装 .NET**。体积大几十 MB，但现场省掉了"客户机器上没装运行时"的麻烦。

## MQTT（W6–W8）

### 发布 / 订阅（Pub/Sub）
消息不直接发给某个人，而是发到一个**主题（Topic）**上；谁订阅了这个主题谁就收到。中间的转发者叫 **Broker**（EMQX 就是一个 Broker）。

### QoS 0 / 1 / 2
消息投递的可靠性档位。**0** 发了就不管（可能丢）；**1** 至少一次（**可能重复**）；**2** 恰好一次（四次握手，最慢）。工业上遥测用 1，控制指令用 1 + 业务层确认。

### 幂等
同一条消息处理一次和处理多次，结果一样。因为 **QoS1 一定会有重复**，所以下游必须幂等——常见做法是给消息带**递增序号**，收到回退的就丢弃。

### Retain（保留消息）
Broker 为每个主题存下**最后一条**，新订阅者一连上立刻收到。适合**状态**（在线/离线），不适合遥测（否则新看板会显示三小时前的温度当现值）。

### LWT（遗嘱消息）
客户端**异常断开**（断电、断网）时，由 Broker 代发的一条预设消息。正常断开不触发。**这是设备离线检测的标准做法。** 最坏延迟是 1.5 × KeepAlive。

### KeepAlive（心跳）
客户端承诺的最大静默时间。Broker 在 1.5 倍这个时间内没收到任何报文就判定失联、发遗嘱。

### 共享订阅
`$share/组名/主题`。同一组内的多个消费者**分摊**消息，而不是每人收一份。**多实例水平扩容的前提。**

### 背压（Backpressure）
上游生产得比下游消费得快时，用**有界队列**挡住上游，而不是让内存无限增长。队列满了要有明确策略：丢最旧、丢最新、还是阻塞。

### 断网续传
断网期间把数据**落到本地磁盘**，网络恢复后按顺序补发。**MQTT 的 QoS 保证不了这个**——连接都建立不了的时候，QoS 无从谈起。

## PLC 与 OPC UA（W9–W12）

### PLC
可编程逻辑控制器，工厂里控制设备动作的专用计算机。程序通常用**梯形图**写，循环执行（读输入 → 算 → 写输出），一轮叫一个**扫描周期**（1–10ms）。

### 梯形图（Ladder）
PLC 的图形化编程语言，看起来像继电器电路图。`┤├` 常开触点、`┤/├` 常闭触点、`( )` 线圈。

### 自锁（启保停）
梯形图里最基础的电路：按钮是点动的（松手就没了），用输出自己的触点并联把状态"锁住"，直到停止按钮断开。**看懂它就看懂了一半的现场程序。**

### DB 块 / I 区 / Q 区 / M 区
西门子 PLC 的存储区。**I** = 输入、**Q** = 输出、**M** = 中间变量、**DB** = 数据块（结构化数据）。地址如 `DB1.DBW2` 表示"第 1 个数据块、偏移 2 字节、读 2 个字节"。

### 优化的块访问（优化块）
S7-1200/1500 新建 DB 块时**默认勾选**的选项。开着它，内存布局由编译器决定，**外部按绝对地址读不到**。现象是读回来全是 0。解法：TIA Portal 里取消勾选。**这是 S7 通信必踩的坑。**

### 大端 / 小端
多字节数值在内存里的排列顺序。**PLC 和网络协议基本都是大端**（高字节在前），**x86/ARM 是小端**。读回来要转，否则数值全错。

### OPC UA
工业互联互通的**事实标准**协议。相比老的 OPC DA：跨平台（不再依赖 Windows COM/DCOM）、内建安全、而且有**带类型的信息模型**而不只是一堆值。

### 地址空间 / 节点 / NodeId
OPC UA 把所有东西组织成一棵有类型的树，每个东西是一个**节点**，用 **NodeId** 标识（如 `ns=2;s=Line1.Motor3.Speed`）。`ns=` 是命名空间下标，**它会变**，所以配置里要存命名空间 URI 而不是下标。

### 订阅 / MonitoredItem
OPC UA 的正确用法：不轮询，而是订阅变量，服务器在值变化时主动推送。`SamplingInterval` 是服务器多久看一眼，`PublishingInterval` 是多久打包发一次。

### 死区（Deadband）
"变化多少才算变了"的阈值。温度死区设 0.5，从 25.0 变到 25.3 不上报，变到 25.6 才上报。**直接用带宽换精度**，几千个点位时这决定了系统扛不扛得住。

### 信任列表 / rejected 目录
OPC UA 的证书机制。客户端第一次连**必然失败**，因为服务器不认识它——要去服务器的 `rejected/` 目录把客户端证书**挪到** `trusted/certs/`，反过来也要做一遍。**"现场老连不上"的头号原因。**

## 数据平台（W13–W16）

### 时序数据库
专门存"带时间戳、只追加、按时间段查"的数据库。相邻数据高度相似，所以能靠列式存储和差值编码压到 1/10——这是 MySQL 做不到的。

### 超级表 / 子表 / 标签（TDengine）
**超级表**是模板（定义列和标签），**一台设备一张子表**继承它。**标签**是不随时间变的属性（站点、产线、设备号），存在元数据里，按标签过滤代价极低。

### 降采样
按时间窗口聚合，比如把秒级数据变成分钟级的平均/最大/最小。**看板必须用它**——屏幕只有 2000 个像素，画 60 万个点没有意义也画不动。

### 分层保留
原始数据留 30 天、分钟级留 1 年、小时级留 3 年。**依据是"超过一个月的秒级数据对生产分析没有意义"**，能把一年 175GB 压到 17GB。

### 回差（Hysteresis）
告警触发用 80，恢复用 78，中间留 2 度的死区。**没有回差，值在 79.9–80.1 抖动时告警会疯狂翻转**，一分钟几十条通知。

### 物模型（属性 / 服务 / 事件）
云平台描述设备的标准抽象。**属性**=状态（可读写），**服务**=能执行的动作（重启、校准），**事件**=设备主动上报的通知（告警）。

### 设备影子
把"期望状态"和"实际状态"分开存。设备离线时你改了配置，改动先存在期望里，设备上线后自动同步。**没有影子，离线期间的指令就丢了。**

## 上位机与交付（W17–W20）

### 上位机
工厂里对着设备的那台电脑上跑的软件，负责显示数据、手动操作、报警。中国工业圈的习惯叫法，对应英文的 HMI / SCADA 客户端。

### 组态软件
组态王、WinCC、力控这类**拖拽画界面**的工业软件。上手快，但脚本能力有限、工程文件是二进制的（没法 code review 和自动化测试）。**这是你自建方案的主要对手。**

### 质量码（Quality）
每个数据点除了值，还要带一个"这个值可不可信"的标记：Good / Bad / Uncertain。**通信断了还继续显示旧值而不标 Bad，是上位机的常见事故。**

### OEE
设备综合效率 = 可用率 × 表现性 × 质量率。工厂最关心的单一指标，你的系统能算出它就是加分项。

### 审计日志
谁、在什么时候、把哪个点位从什么值改成了什么值、结果如何。**工业软件的硬要求**，出事故要能追溯。
