## 一、S7comm 是什么

西门子的私有协议，跑在 **ISO-on-TCP（RFC1006）**上，端口 **102**。不是公开标准，社区靠逆向实现了客户端库。

| 库 | 说明 |
|---|---|
| **S7.Net Plus** | 纯 C# 实现，NuGet 直接装，API 最简单，**首选** |
| **Sharp7** | Snap7 的 C# 单文件移植，无依赖，适合嵌入 |
| Snap7 | C++ 原版，还提供了一个 **Server 模拟器**——没真机时用它 |

连接三要素：**IP + Rack + Slot**。

| PLC | Rack | Slot |
|---|---|---|
| S7-1200 / 1500 | 0 | **1** |
| S7-300 | 0 | 2 |
| S7-400 | 0 | 通常 2 或 3 |

**连不上时第一个怀疑 Slot 填错了**——1200 填 2 是最常见的错。

## 二、优化块：这周一定会踩的坑

S7-1200/1500 新建 DB 块时，**默认勾选"优化的块访问"（Optimized block access）**。

| | 优化块 | 非优化块（标准） |
|---|---|---|
| 内存布局 | **编译器决定**，你看不到也算不出 | 按声明顺序线性排列 |
| 访问方式 | 只能**按符号名** | 可以按绝对地址 `DB1.DBW2` |
| S7.Net 读取 | **读不到** | 正常 |
| 性能 | 略好 | 略差 |

**现象**：代码没报错，但读回来的全是 0，或者直接抛异常。

**解法**：TIA Portal 里右键 DB 块 → 属性 → **取消勾选"优化的块访问"** → 重新编译下载。

> **这个坑必须亲手踩一遍。** 面试问"S7 读 DB 块有什么坑"，答"优化块读不到绝对地址，要在 TIA 里关掉优化访问"，对方立刻知道你上过手。答"没什么坑"就露馅了。
>
> 顺带一提：**关闭优化会改变内存布局**，如果 PLC 程序里已经有代码按符号访问这个 DB，关掉后仍然能用（符号访问始终有效），但**下载会清空 DB 的当前值**——生产线上做这个操作要提前打招呼。

## 三、手算绝对地址

```
DB1:
  bStart      Bool     → DB1.DBX0.0
  bStop       Bool     → DB1.DBX0.1
  bRunning    Bool     → DB1.DBX0.2
                         （三个布尔挤在第 0 字节的三个位里）
  iCount      Int      → DB1.DBW2      ← 跳到 2，因为 Int 要 2 字节对齐
  rTemp       Real     → DB1.DBD4      ← Real 要 4 字节对齐
  rPressure   Real     → DB1.DBD8
  sName       String[10] → DB1.DBB12 起，共 12 字节
                           （String 头 2 字节：最大长度 + 当前长度）
```

**三条对齐规则**：

1. `Bool` 按位排，同一字节能塞 8 个
2. `Int`/`Word` 从**偶数字节**开始
3. `Real`/`DInt`/`DWord` 从 **4 的倍数**开始
4. 遇到 `Bool` 之后接非 `Bool`，剩余的位被浪费掉，直接跳到下一个对齐边界

**验证方法**：TIA Portal 里把 DB 块切到"数据视图"，**偏移量那一列是现成的答案**。手算一遍再对答案，算错的地方就是你没理解的对齐规则。

## 四、读写代码

```csharp
using S7.Net;

var plc = new Plc(CpuType.S71200, "192.168.1.10", rack: 0, slot: 1);
await plc.OpenAsync();

// 读单个
var count  = (short)plc.Read("DB1.DBW2");
var temp   = (float)plc.Read("DB1.DBD4");
var running = (bool)plc.Read("DB1.DBX0.2");

// 写：上位机按钮 → PLC 输出
await plc.WriteAsync("DB1.DBX0.0", true);

// 批量读——一次读一整段，比逐个读快一个数量级
var raw = plc.ReadBytes(DataType.DataBlock, db: 1, startByteAdr: 0, count: 24);
var t   = BinaryPrimitives.ReadSingleBigEndian(raw.AsSpan(4, 4));
```

**批量读是性能关键**，和 Modbus 的批量读优化是同一个思路：**一次通信的固定开销远大于多读几个字节**。W3 写的 `ReadPlanner` 思路可以直接复用到 S7 驱动上。

**S7 的单次读取也有上限**（PDU 大小，通常 240 或 480 字节，握手时协商）。超过要自动分片——这是封装驱动时必须处理的。

## 五、封装成 `Iiot.Drivers.S7`

**接口必须和 Modbus 驱动完全一致**——这是 W12 统一抽象的前提，也是整个项目架构价值的体现。

```csharp
public sealed class S7Driver(IS7Connection conn, S7DriverOptions options) : IDeviceDriver
{
    public Task ConnectAsync(CancellationToken ct = default);
    public Task<IReadOnlyList<TagValue>> ReadAsync(IReadOnlyList<TagDefinition> tags, CancellationToken ct);
    public Task WriteAsync(TagDefinition tag, object value, CancellationToken ct);
    public DriverStatistics Statistics { get; }
}
```

**`TagDefinition` 里的地址字段要能同时表达两种协议**：Modbus 是 `区 + 偏移`，S7 是 `DB号 + 字节偏移 + 位偏移`。做法是存字符串（`"DB1.DBD4"` / `"4x0001"`），由各驱动自己解析——**不要试图设计一个能表达所有协议的通用地址结构**，那是过度抽象。
