# W11 · OPC UA 客户端

> 题库: Q20, Q21, Q22

OPC UA 是**工业互联互通的事实标准**，也是这半年里技术含量最高的一块。会 Modbus 的人很多，会 OPC UA 的少得多——这就是分水岭的含义。

---

## 一、比 OPC DA 好在哪（Q20）

老 OPC（DA/HDA/AE）建立在 **Windows COM/DCOM** 上。这一句话就解释了它所有的痛：

| | OPC DA（经典） | OPC UA |
|---|---|---|
| 技术底座 | COM/DCOM，**只能 Windows** | TCP + 二进制/HTTPS，**跨平台** |
| 跨机器 | DCOM 配置是运维噩梦，防火墙几乎不可能配对 | 一个 TCP 端口（4840） |
| 安全 | 靠 Windows 域认证 | **内建**：证书、签名、加密、用户令牌 |
| 数据模型 | 平铺的 Item 列表 | **地址空间**——带类型、层级、引用的信息模型 |
| 语义 | 只有值 | 可以描述"这是一台电机，它有转速属性和启动方法" |

**最值得强调的是第四行**：DA 给你一堆 `Channel1.Device1.Tag0042`，你不知道它是什么；UA 给你一棵有类型的树，客户端可以**自己发现**结构。这是"数据"和"信息"的区别。

跨平台和防火墙友好是现实中让大家换过来的直接原因（DCOM 在跨网段时基本没法配）。

## 二、地址空间与 NodeId

一切都是**节点（Node）**，节点之间用**引用（Reference）**连接，构成一张有向图（通常按 `Organizes`/`HasComponent` 看成树）。

**NodeId = NamespaceIndex + Identifier**，四种标识符类型：

| 类型 | 写法 | 说明 |
|---|---|---|
| **Numeric** | `ns=2;i=1001` | 最紧凑，服务器内部常用 |
| **String** | `ns=2;s=Line1.Motor3.Speed` | **最常见**，可读性最好 |
| GUID | `ns=2;g=...` | 需要全局唯一时 |
| Opaque | `ns=2;b=...` | 二进制，罕见 |

**`ns=` 那个数字是会变的**——它是命名空间 URI 在**本次会话**的服务器命名空间表里的下标。服务器重启或加载不同配置后，同一个 URI 可能拿到不同的 index。

> **这是个真实的坑**：把 `ns=2;s=Foo` 硬编码进配置，某天服务器加了个新命名空间，`ns=2` 变成了别的东西，你的点表全废。
>
> **正确做法**：存**命名空间 URI**（比如 `http://mycompany.com/line1/`）+ Identifier，连接后调 `ReadNamespaceTableAsync()` 动态解析出当前的 index。

## 三、订阅机制与 Deadband（Q21）

不要轮询。UA 的正确用法是**订阅 + 变化上报**。

```
Subscription（订阅）
  ├── PublishingInterval  服务器多久打包发一次通知（比如 1000ms）
  └── MonitoredItem（每个被监视的变量一个）
        ├── SamplingInterval  服务器多久去采一次这个变量（比如 250ms）
        ├── QueueSize         两次发布之间最多缓存几个变化
        └── DataChangeFilter  什么样的变化才算"变了"
```

**两个 Interval 的关系**（面试常问）：

```
SamplingInterval = 250ms   ← 服务器每 250ms 看一眼这个变量变没变
PublishingInterval = 1000ms ← 每 1000ms 把攒下的变化打包发给客户端
QueueSize = 4              ← 1000/250 = 4，正好装得下
```

**`QueueSize` 设小了会丢中间值**：采样 250ms、发布 1000ms、队列只有 1，那一秒内的 4 次变化你只收到最后 1 次。要完整轨迹就把 `QueueSize ≥ PublishingInterval / SamplingInterval`。

**Deadband（死区）**：过滤掉无意义的抖动。

| 类型 | 含义 | 例子 |
|---|---|---|
| `None` | 任何变化都报 | 布尔量、状态字 |
| **`Absolute`** | 变化量 > N 才报 | 温度死区 0.5℃ |
| `Percent` | 变化超过量程的 N% 才报 | 需要变量声明了 EURange |

**必做实验**：绝对死区设 0.5，让值从 25.0 变到 25.3（不上报）再到 25.6（上报）。**亲眼看过一次，面试就能讲得具体。**

> 死区是**带宽和精度的直接交换**。一个 0–100℃ 的温度点，死区 0.5 能把上报量减少 90% 以上。现场几千个点位时，这决定了系统扛不扛得住。

## 四、证书：现场为什么老连不上（Q22）

**这是 OPC UA 最劝退的部分，也是最值得讲的踩坑故事。**

安全策略从低到高：

| 策略 | 说明 |
|---|---|
| `None` | 不签名不加密。**只用于内网调试** |
| `Basic256Sha256` | 签名 + 加密，**当前推荐** |
| `Aes128_Sha256_RsaOaep` / `Aes256_...` | 更新的策略 |

**信任是双向的**，这是最多人卡住的地方：

```
客户端                          服务器
  ├─ own/          自己的证书      ├─ own/
  ├─ trusted/certs 信任的对方 ←──── 客户端证书要放进这里
  └─ rejected/     被拒绝的     ────→ 首次连接失败后，客户端证书掉进这里
```

**标准操作流程**：

1. 客户端第一次连，**必然失败**（服务器不认识它）
2. 去服务器的 `rejected/` 目录，把客户端证书**移到** `trusted/certs/`
3. 反过来同理：把服务器证书放进客户端的 `trusted/`
4. 再连，成功

**其他常见失败原因**：

- **主机名不匹配**：证书里的 `ApplicationUri` / SAN 和你连接用的地址对不上。用 IP 连而证书里写的是主机名，直接被拒。
- **证书过期**：自签证书默认往往只有 1 年，一年后现场"突然连不上"。
- **时间不同步**：两台机器时钟差太多，证书有效期判断失败。**这个最阴**——现象是"昨天还好好的"。
- **端点 URL 不一致**：服务器返回的 `EndpointUrl` 是内网地址，你从外网连，客户端拿到后按它重连就失败。UA-.NETStandard 里可以用 `UseSecurity=false` 或覆盖端点来绕。

> 面试话术："第一次连必然失败，因为服务器不认识客户端证书。要去 `rejected` 目录把证书挪到 `trusted/certs` 再连，两边都要做。后来还遇到过时钟不同步导致的证书校验失败，现象是昨天好好的今天连不上，查了半天才想到看时间。"

## 五、客户端代码骨架

```csharp
var config = new ApplicationConfiguration
{
    ApplicationName = "IiotClient",
    ApplicationType = ApplicationType.Client,
    ApplicationUri  = "urn:iiot:client",          // 必须和证书里一致
    SecurityConfiguration = new SecurityConfiguration
    {
        ApplicationCertificate = new CertificateIdentifier { /* own/ */ },
        TrustedPeerCertificates = new CertificateTrustList { /* trusted/certs */ },
        AutoAcceptUntrustedCertificates = false,   // 调试时可 true，生产必须 false
    },
};
await config.Validate(ApplicationType.Client);

var endpoint = CoreClientUtils.SelectEndpoint("opc.tcp://192.168.1.20:4840", useSecurity: true);
using var session = await Session.Create(config, new ConfiguredEndpoint(null, endpoint), false, "IiotClient", 60000, null, null);

var sub = new Subscription(session.DefaultSubscription) { PublishingInterval = 1000 };
sub.AddItem(new MonitoredItem(sub.DefaultItem)
{
    StartNodeId = new NodeId("Line1.Motor3.Speed", nsIndex),
    SamplingInterval = 250,
    QueueSize = 4,
    Filter = new DataChangeFilter
    {
        DeadbandType = (uint)DeadbandType.Absolute,
        DeadbandValue = 0.5,
        Trigger = DataChangeTrigger.StatusValue,
    },
});
session.AddSubscription(sub);
sub.Create();
```

**`AutoAcceptUntrustedCertificates = true` 只在调试时开**。生产环境开着等于把 UA 的安全全废了——面试官问到会追。
