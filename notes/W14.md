## 一、连上 TDengine

Grafana 需要 TDengine 数据源插件：

插件已收录进 Grafana 官方目录，直接装即可：

```bash
docker exec -it grafana grafana-cli plugins install tdengine-datasource
docker restart grafana
```

但**手动装一次不算数**。M4 闸门要求 `docker-compose up` 能把 EMQX + TDengine + Grafana
全起来，所以要写进 compose：

```yaml
grafana:
  image: grafana/grafana:latest
  environment:
    GF_INSTALL_PLUGINS: tdengine-datasource
```

这样在一台干净机器上 clone 下来就能跑——**这才叫"一键起"**。

## 二、一块看板该有什么

按**从粗到细**排布，让人一眼知道"现在有没有事"：

```
┌─────────────────────────────────────────────┐
│ 在线设备 48/50 │ 活动告警 2 │ 今日写入 3.7亿 │  ← Stat 面板，一眼看健康
├─────────────────────────────────────────────┤
│           产线温度趋势（多设备叠加）           │  ← Time series，主视图
├──────────────────────┬──────────────────────┤
│  设备通信质量表        │   最近告警列表        │
│  （成功率 / P99 时延） │                      │
└──────────────────────┴──────────────────────┘
```

**通信质量表是你的差异化**。多数人的看板只有工艺数据；把 W4 采集的成功率、P99 时延也画出来，直接体现"我做过运维视角的设计"。用**颜色阈值**：>98% 绿、90–98% 黄、<90% 红——那个黄色区间就是 W4 说的"劣化"。

## 三、模板变量：一块看板服务所有产线

不要给每条产线复制一块看板。用变量：

```
变量 line:  SELECT DISTINCT line FROM meter
变量 device: SELECT DISTINCT device_id FROM meter WHERE line = '$line'   ← 级联
```

查询里用 `WHERE line = '$line'`，顶部就出现下拉框。**`$device` 依赖 `$line` 的级联关系**是关键——选了产线，设备下拉自动收窄。

**必须用 Grafana 的时间宏**，不要写死时间：

```sql
SELECT _wstart, AVG(temp) FROM meter
WHERE line = '$line' AND ts >= $from AND ts < $to
INTERVAL($__interval)
```

`$__interval` 会**根据当前时间范围自动选聚合粒度**——看 1 小时给你秒级，看 1 年给你小时级。这是看板不卡的关键，也是 W13 降采样的实际应用。

## 四、告警：阈值不够，还要持续时间

**只有阈值的告警一定会被关掉。** 温度在 79.8 和 80.2 之间抖动，一分钟发五十条告警，运维第二天就把通知静音了。

四个必备维度：

| 维度 | 作用 | 例子 |
|---|---|---|
| **阈值** | 什么算异常 | temp > 80 |
| **持续时间** | 抖动不算 | 持续 **2 分钟**才触发 |
| **分级** | 别把所有事当天塌 | 提示 / 警告 / 严重 |
| **恢复通知** | 知道什么时候好了 | 恢复时也发一条 |

**去抖（防抖动）的两种做法**：

1. **`FOR` 子句**：Grafana 告警规则里的 "pending period"——条件持续满足 N 分钟才真正触发
2. **回差（hysteresis）**：触发用 80，恢复用 **78**。留 2 度的死区，值在 79–81 之间抖动时状态不会来回翻。

> 回差这个词能说出来是加分项，它和 W11 的 Deadband 是同一个思想在不同层的应用。

**告警本身也要能查历史**——W18 会把告警落库，这样才能回答"上个月这台设备报了几次警"。

## 五、数据分层策略（文档产出）

W13 算出来的策略，这周写成一页文档：

| 层 | 精度 | 保留 | 生成方式 | 用途 |
|---|---|---|---|---|
| 原始 | 1 秒 | 30 天 | 直接写入 | 故障回溯、精确排查 |
| 分钟 | 1 分钟 | 1 年 | 流式计算聚合 | 日常看板、趋势 |
| 小时 | 1 小时 | 3 年 | 流式计算聚合 | 报表、同比环比 |

**看板默认查分钟表**，只有明确缩到几小时内才落到原始表。这个"自动选层"可以用 Grafana 的多查询 + `$__interval` 判断实现。
