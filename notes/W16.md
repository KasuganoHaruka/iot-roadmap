## 二、物模型：三要素

**这是云平台最值得学的抽象**，比具体的 API 重要得多。

| 要素 | 含义 | 例子 | 对应到你的项目 |
|---|---|---|---|
| **属性 Property** | 设备的状态，可读可写 | 温度（只读）、采集周期（读写） | 点表里的 tag |
| **服务 Service** | 设备能执行的动作 | 重启、立即上报、校准 | W8 的远程配置下发 |
| **事件 Event** | 设备主动上报的通知 | 超温告警、故障码 | W18 的告警 |

**为什么这个抽象重要**：它把"设备"从一堆点位变成了**有行为的对象**。你的 `IDeviceDriver` 目前只有属性（读写 tag），没有服务和事件的概念——**这是可以在面试里主动提的改进方向**，说明你想过下一步。

物模型定义完，云平台会自动生成设备端 SDK、Topic 规范、以及控制台的调试页面。**这就是标准化的价值。**

## 三、三元组鉴权

设备接入的身份是 **ProductKey + DeviceName + DeviceSecret**（华为叫设备 ID + 密钥，概念一样）。

MQTT 连接时：

- `clientId` 由三元组按规则拼装（各家格式不同，抄文档）
- `username` / `password` 用 **HMAC-SHA1/SHA256 签名**算出来，不是明文密钥

**为什么不是直接传密钥**：签名里带时间戳，防重放；密钥本身不上网。

**一机一密 vs 一型一密**：

| | 一机一密 | 一型一密（动态注册） |
|---|---|---|
| 密钥 | 每台设备烧录不同密钥 | 同型号共用产品密钥，首次连接时动态申请设备密钥 |
| 产线 | 麻烦（每台要烧不同的） | **简单**（镜像统一） |
| 安全 | 更好 | 首次注册窗口有风险 |

**产线量产时基本都用一型一密**，这个取舍面试可以聊。

## 四、设备影子与 OTA

**影子**（和 W15 的 ThingsBoard 是同一概念）：

```
期望状态 desired: { "interval": 5000 }   ← 你在控制台改的
实际状态 reported: { "interval": 1000 }  ← 设备当前的
                                          设备上线后拉取 desired，执行，回写 reported
```

**必做实验**：把设备**关掉**，在控制台改配置，再把设备打开——看它是否自动同步。这就是影子的全部价值。

**OTA**：走一遍上传升级包 → 创建升级批次 → 设备接收 → 上报进度 → 完成。

嵌入式 OTA 的关键点（即使这周只是走流程，也要知道）：
- **断点续传**（弱网下几 MB 的包要传很久）
- **校验**（下完要校验 MD5/SHA，不能装个坏包）
- **A/B 分区或回滚**（升级失败要能退回旧版本，否则设备变砖）
- **灰度**（先升 1%，观察，再全量）

## 五、规则引擎：转发到自建服务

```
设备数据 → 云平台规则引擎 → HTTP 转发到你的服务
                          → 或写入云上的时序库
                          → 或触发函数计算
```

**必做**：配一条规则，把遥测转发到你自己的 HTTP 服务，验证收到了。

**这条链路的意义**：证明云平台和自建方案**可以共存**——设备接云平台（拿它的设备管理、OTA、影子），数据再转回自己的系统（做业务分析）。面试时这是个成熟的架构观点，比"要么全云要么全自建"高一档。
