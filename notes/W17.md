## 一、三个驱动接进同一个调度

W12 定好的 `IDeviceDriver` 现在要真的跑起来。调度器**只认接口**，不认协议：

```csharp
public sealed class CollectorService(
    IEnumerable<IDeviceDriver> drivers,
    IMeasurementBuffer buffer,
    IOptionsMonitor<GatewayOptions> opts) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        // 每台设备一个独立的采集循环，周期各自配置
        var loops = drivers.Select(d => RunDeviceLoop(d, ct));
        await Task.WhenAll(loops);
    }
}
```

**一个关键设计**：共享 485 总线上的设备**不能并行**（W4 讲过），独立 TCP 链路的可以。所以调度要按**传输通道**分组，同组串行、跨组并行。

```
通道 A（/dev/ttyModbus0）：设备1 → 设备2 → 设备3 → 循环   ← 串行
通道 B（192.168.1.10:102）：PLC                            ← 并行
通道 C（opc.tcp://...:4840）：OPC UA Server                ← 并行
```

**这个分组本身就是面试素材**——它证明你理解物理层约束，而不是把所有设备当成一样的。

## 二、点表：Excel / JSON 导入

现场交付时，点表是**电气工程师给你的 Excel**，不是你手写的 JSON。

| 列 | 说明 | 来自哪一周的教训 |
|---|---|---|
| 设备ID / 名称 | | |
| 驱动类型 | modbus-rtu / modbus-tcp / s7 / opcua | W12 |
| 地址 | `4x0001` / `DB1.DBD4` / `ns=2;s=...` | W3/W10/W11 |
| 数据类型 | Int16 / Float32 / Bool | |
| **字序** | ABCD / CDAB / BADC / DCBA | **W3** |
| 缩放系数 | 原始值 × scale + offset | 仪表返回 255 表示 25.5 |
| 单位 | ℃ / rpm / kW | W12 的 EngineeringUnits |
| 采集周期 | 按变化速率分级 | **W4** |
| 报警上下限 | 给 W18 的告警引擎 | |

用 **ClosedXML** 或 **ExcelDataReader** 读 xlsx（都不需要装 Office）。

**导入必须有校验并给出人话错误**：

```
第 12 行：地址 "4x70000" 超出保持寄存器范围（最大 4x65536）
第 25 行：字序 "ABDC" 不是有效值，应为 ABCD/CDAB/BADC/DCBA
第 31 行：设备 line1-meter-003 的采集周期 50ms 低于该总线的物理下限 600ms
```

**最后一条尤其加分**——它说明你把 W4 算的总线带宽用起来了，在导入时就拦住了不可能实现的配置。

## 四、通信质量上报

W4 采集的统计数字，这周要**作为数据发出去**——它和工艺数据一样重要。

```
主题：iiot/{site}/{line}/{device}/diagnostics
载荷：{ "successRate": 0.987, "avgLatencyMs": 82, "p99LatencyMs": 340,
        "timeouts": 12, "consecutiveFailures": 0, "ts": 1788850000000 }
```

上报周期比遥测慢得多（比如 30 秒一次）——它是趋势，不是实时值。

**为什么值钱**：W14 的看板上有一块"设备通信质量"，数据就来自这里。多数人的系统只有工艺数据，**你的系统能告诉运维"3 号表的成功率从 99% 掉到 91% 了，去看看接线"**——这是在故障发生前发现问题。

## 五、边缘计算在这套系统里做什么（Q27）

面试常问，答案不是"边缘计算就是在边缘算"。**具体列出你的系统在边缘做了什么、为什么必须在边缘做**：

| 边缘做的事 | 为什么不能放云端 |
|---|---|
| **协议转换** | Modbus/S7 是本地总线协议，根本出不了厂区 |
| **断网续传** | 云端不知道你断网了，缓冲必须在断点的这一侧 |
| **数据过滤/死区** | 上报量直接决定带宽成本；1000 个点全量上云是浪费 |
| **本地联锁/快速响应** | 超温要立刻停机，走一趟云端几百毫秒，来不及 |
| **时间戳** | 数据发生的时刻只有边缘知道（W8 讲过补传会让平台时间失真） |
| **数据脱敏** | 有些工厂不允许原始数据出厂区，边缘先聚合 |

**一句话版本**："边缘负责**贴着设备才能做的事**——协议、断网、实时性、时间戳；云端负责**聚合了才有意义的事**——跨厂区对比、长周期趋势、模型训练。分界线是'这件事需不需要贴着设备'。"
