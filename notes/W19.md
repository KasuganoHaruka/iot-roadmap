## 一、骨架：MVVM，但别过度

```csharp
public sealed partial class TagMonitorViewModel : ObservableObject
{
    [ObservableProperty] private ObservableCollection<TagRow> _rows = [];
    [ObservableProperty] private bool _isConnected;

    [RelayCommand(CanExecute = nameof(CanWrite))]
    private async Task WriteValueAsync(TagRow row) { /* ... */ }

    private bool CanWrite(TagRow row) => IsConnected && row.Writable;
}
```

用 **CommunityToolkit.Mvvm** 的源生成器（`[ObservableProperty]` / `[RelayCommand]`），省掉大量样板。**不要自己手写 `INotifyPropertyChanged`**，也不要引入重型框架（Prism 之类）——这是个演示项目，架构复杂度要和规模匹配。

**UI 线程的铁律**：数据从 MQTT/驱动线程来，更新 UI 必须回到 UI 线程。

```csharp
// 高频更新时，不要每条数据都 Dispatcher.Invoke 一次——会把 UI 线程打死
// 攒 100ms 一批，一次性更新
_uiTimer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(100) };
_uiTimer.Tick += (_, _) => ApplyPendingUpdates();
```

**这个批量刷新是性能关键**。1000 个点位每秒更新一次 = 每秒 1000 次 `Invoke`，UI 会卡到没法用。攒批后是每秒 10 次。

## 二、实时曲线：1000 点以上不卡

| 库 | 特点 |
|---|---|
| **ScottPlot** | 性能最好，API 简单，**首选** |
| LiveCharts2 | 动画漂亮，MVVM 友好，大数据量吃力 |
| OxyPlot | 老牌，功能全 |

**卡顿的三个原因和对策**：

1. **点太多**：屏幕只有 2000 像素，画 10 万个点没有意义。**显示前先降采样**（和 W13 的看板降采样是同一个道理）。
2. **每来一个点就重绘**：改成定时重绘（10 fps 足够，人眼看不出差别）。
3. **用了带动画的图表库**：实时曲线关掉动画。

```csharp
// ScottPlot 的滚动缓冲：固定容量，自动丢最旧的
var data = new ScottPlot.DataStreamer(plot, 1000);
// 数据线程只 Add，UI 定时器负责 Refresh
```

## 三、点位监视表格

```
设备      点位        值      单位   质量   更新时间     状态
line1-01  Temperature 25.3    °C     Good   12:03:41     ●绿
line1-01  Humidity    62.1    %      Good   12:03:41     ●绿
line1-02  Pressure    ---     kPa    Bad    12:01:07     ●红
```

**颜色标识通信状态**是现场人员最看重的一列。三态而不是两态（W4 讲过）：

- ● 绿 = 正常（成功率 > 98%）
- ● 黄 = **劣化**（90–98%，接线可能松了）
- ● 红 = 离线

**质量码要显示出来**。`Bad` 质量的值不能当好数据用——很多上位机把通信失败时的旧值继续显示，运维看着是正常的，其实数据已经十分钟没更新了。**显示"最后更新时间"**能把这个问题暴露出来。

大数据量用 `VirtualizingStackPanel`（`DataGrid` 默认开启），几千行才不卡。

## 四、手动写值：二次确认 + 审计

**这是上位机最危险的功能**——写错一个值可能让产线停机或损坏设备。

```csharp
private async Task WriteValueAsync(TagRow row)
{
    // 1. 范围校验
    if (value < row.Min || value > row.Max)
    { Show($"值超出范围 [{row.Min}, {row.Max}]"); return; }

    // 2. 二次确认，把关键信息重复一遍
    var ok = Confirm($"确认向 [{row.Device}] 的 [{row.Tag}] 写入 {value} {row.Unit}？\n"
                   + $"当前值：{row.Value} {row.Unit}");
    if (!ok) return;

    // 3. 写入
    await driver.WriteAsync(row.Definition, value, ct);

    // 4. 审计日志——谁、什么时候、写了什么、结果如何
    audit.Record(user: Environment.UserName, device: row.Device, tag: row.Tag,
                 oldValue: row.Value, newValue: value, result: "OK");
}
```

**审计日志是工业软件的硬要求**，不是可选项。出了事故要能追溯是谁在什么时候改了什么。**面试时主动提这一点，会显得你懂现场规矩。**

**权限**：写值应该和只读分开。演示项目做个简单的角色开关即可，但要能说出"生产环境这里要接 LDAP/域账号"。

## 五、报警列表

```
级别  时间       设备      点位   触发值  状态    确认人
严重  12:01:07  line1-02  Temp   85.3   活动     -
警告  11:47:22  line1-01  Press  ---    已恢复   张三
```

**必备功能**：
- **未确认的置顶 + 高亮**，不能让新告警滚出视野
- **确认（Acknowledge）**：记录确认人和时间——这是"有人看见了"的凭证
- **恢复的告警不立刻消失**，保留一段时间，否则运维会错过短暂告警
- **历史查询**：按时间范围 + 设备 + 级别过滤
