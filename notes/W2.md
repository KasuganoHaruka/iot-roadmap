## 一、四个数据区：先把地址模型搞对

Modbus 的数据模型只有四块，理解了这个，功能码表就不用背了。

| 区 | 传统记法 | 类型 | 读写 | 功能码 |
|---|---|---|---|---|
| 线圈 Coil | `0xxxx` | 位 | 读写 | 读 **01**，写单个 **05**，写多个 **0F** |
| 离散输入 | `1xxxx` | 位 | 只读 | 读 **02** |
| 输入寄存器 | `3xxxx` | 16 位字 | 只读 | 读 **04** |
| 保持寄存器 | `4xxxx` | 16 位字 | 读写 | 读 **03**，写单个 **06**，写多个 **10** |

**03 和 04 的区别**就是这张表的两行：03 读保持寄存器（可读可写），04 读输入寄存器（只读）。

> **实战补充**：很多国产设备偷懒，把所有数据都塞进保持寄存器、只实现 03。拿到新设备第一件事是看手册的寄存器表，不要想当然。

### 地址差 1 的经典陷阱

传统 PLC 文档用 **1-based 的 4xxxx 记法**，协议报文里是 **0-based**：

- 文档写 `40001` → 报文里填 `0`
- 文档写 `40100` → 报文里填 `99`

**看到 4 开头的 5 位数就要警觉**。有些手册直接给协议地址，有些给 4xxxx 地址，混用是现场"数据全错位"的头号原因。

## 二、两种帧格式

### RTU（串口）

```
┌────────┬─────────────────┬──────────┐
│ 从站地址 │       PDU        │  CRC16   │
│  1 字节  │   功能码 + 数据   │  2 字节  │
└────────┴─────────────────┴──────────┘
                              低字节在前
```

### TCP（以太网，端口 502）

```
┌──────────────── MBAP 7 字节 ────────────────┬─────────┐
│ 事务ID(2) │ 协议ID(2) │ 长度(2) │ 单元ID(1) │   PDU   │
└──────────────────────────────────────────────┴─────────┘
    全部大端        恒为 0    后续字节数        无 CRC
```

**中间那段 PDU 两者完全一样。** 这就是为什么驱动应该把传输层抽象成 `IModbusTransport` —— RTU 和 TCP 真正不同的只有**外壳和校验**，上层编解码写一遍就够。W3 要做的就是这件事。

TCP 没有 CRC，因为 TCP 自己保证完整性。长度字段 = 单元ID + PDU 的字节数（注意包含单元 ID）。

## 三、FC03 逐字节（本周的核心）

**请求**：从站 1，读保持寄存器，起始地址 0，读 10 个

```
01   03   00 00   00 0A   C5 CD
│    │    └──┬──┘ └──┬──┘ └──┬─┘
│    │       │       │       └─ CRC16，低字节 C5 在前
│    │       │       └───────── 寄存器数量 = 10（大端）
│    │       └───────────────── 起始地址 = 0（大端）
│    └───────────────────────── 功能码 03
└────────────────────────────── 从站地址 1
```

**响应**：

```
01   03   14   00 7B  00 00  ...   CRC(2)
│    │    │    └──┬─┘
│    │    │       └─ 第 1 个寄存器 = 0x007B = 123
│    │    └───────── 字节计数 = 20（10 个寄存器 × 2）
│    └────────────── 功能码 03（回显）
└─────────────────── 从站地址
```

**响应第 3 字节是字节计数** —— 这就是分帧的钥匙：先读 3 字节，拿到 N，再读 N+2 字节（数据 + CRC）。W1 那个分帧器在这里派上用场。

### 一次最多能读多少

| 功能码 | 上限 |
|---|---|
| FC03 / FC04 读寄存器 | **125** 个（0x7D） |
| FC01 / FC02 读位 | **2000** 个（0x7D0） |
| FC10 写多个寄存器 | **123** 个（0x7B） |
| FC0F 写多个线圈 | 1968 个 |

**125 是怎么来的**：RTU 帧最大 256 字节。响应 = 1 地址 + 1 功能码 + 1 字节计数 + N×2 数据 + 2 CRC = 5 + 2N ≤ 256 → N ≤ 125。

W3 的批量读优化必须夹在这个上限里。

## 四、CRC16：本周唯一要写的代码

参数：多项式 **0xA001**（0x8005 的位反转）、初值 **0xFFFF**、无输出异或。

```
crc = 0xFFFF
对每个字节 b：
    crc ^= b                      ← 注意是异或到低 8 位
    重复 8 次：
        若 crc 最低位为 1： crc = (crc >> 1) ^ 0xA001
        否则：             crc = crc >> 1
```

**自检向量**：`"123456789"` → `0x4B37`。这是所有 CRC 实现的通用校验值，算不出这个就是实现错了。

> 手边留一个在线校验器对答案：<https://crccalc.com/> —— 选 **CRC-16/MODBUS**，
> 把你的报文十六进制粘进去，和自己算的比。调试 CRC 时这比 print 快得多。

**真实报文**：`01 03 00 00 00 0A` → CRC = `0xCDC5`，**传输时写成 `C5 CD`**。

### 为什么低字节在前

Modbus 的**数据域是大端**（高字节在前），但 **CRC 是小端**（低字节在前）。这是规范里的历史遗留不一致，**推不出来，只能记住**。而 Modbus TCP 的 MBAP 头**全部是大端**。

面试很爱问这个，因为它能一秒区分"读过规范"和"只调过库"。

> 你仓库里 `Crc16.cs` 的 `Compute` 和 `ComputeFast` 就是这周的作业。测试已经写好了（`Crc16Tests`），把它们变绿即可。查表法要预生成 256 项，结果必须和逐位法完全一致。

## 五、异常响应

从站出错时，**功能码 + 0x80**，后跟一个字节的异常码：

```
01   83   02   C0 F1
     │    │
     │    └─ 异常码 02 = 非法数据地址
     └────── 0x03 + 0x80 = 0x83，表示这是异常响应
```

| 码 | 含义 | 现场最常见的原因 |
|---|---|---|
| 01 | 非法功能码 | 设备不支持 04，只支持 03 |
| **02** | **非法数据地址** | **地址越界，或 4xxxx 没减 1** |
| 03 | 非法数据值 | 数量超过 125，或写入值超范围 |
| 04 | 从站设备故障 | 设备内部错误 |
| 06 | 从站忙 | 上一条还没处理完 |

**本周必做**：故意读一个越界地址，抓到 `0x83 + 02`。亲手触发过一次，比看表记得牢。

解析时要**把异常码转成有意义的业务异常**，不要吞掉——W3 的任务里有这一条。

## 六、本周的工具活

1. **下载规范原文**（modbus.org 免费，无需注册，直接下载）：
   - 应用协议：<https://www.modbus.org/file/secure/modbusprotocolspecification.pdf>
   - 串行链路：<https://www.modbus.org/file/secure/modbusoverserial.pdf>
   - 索引页（还有 Modbus Security、一致性测试等）：<https://www.modbus.org/modbus-specifications>

   > 注意：站点已改版，文件名不再是路线图里写的 `Modbus_Application_Protocol_V1_1b3.pdf`，
   > 但内容就是那份应用协议规范。**通读一遍**，不用背，知道去哪查即可。

2. **装一个从站模拟器**，三选一：
   - [diagslave](https://www.modbusdriver.com/diagslave.html) —— 免费，命令行，Linux/Windows 都有，最省事
   - [Modbus Poll / Modbus Slave](https://www.modbustools.com/) —— Windows 图形界面，业界最常用，有试用期
   - [pymodbus](https://github.com/pymodbus-dev/pymodbus) —— 免费且可脚本化，方便造异常响应等边界情况

3. **Wireshark 抓 Modbus TCP**（<https://www.wireshark.org/download.html>），把 MBAP 头四个字段逐个对上。
   Wireshark 自带 Modbus 解析器，字段名对照见
   <https://www.wireshark.org/docs/dfref/m/modbus.html> ——
   但**先自己按字节数一遍再看它的解析结果**，否则等于没抓。
   过滤器直接输 `modbus`，或 `tcp.port == 502`。

4. 纸上手写 01/02/03/04/05/06/0F/10 八个功能码的请求与响应结构。
