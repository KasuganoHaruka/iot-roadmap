# W24 · 收口与谈判

> 题库: —

最后一周。**拿到 offer 只是一半，谈明白才是另一半。**

## 开始之前

**这周做什么** — 谈明白，或者拿到一份精确的「还差什么」清单。

**读完你能** — 说出你的理想/目标/底线三个数；把薪资以外的六项都问清。

**需要什么** — 手上最好有两个 offer 再谈。本周末是 M6 闸门。

**12 小时怎么分** — 继续面试与复盘 6h · 谈判准备 2h · **谈判 2h** · 填完 progress.md 2h

---

## 一、谈判的前提：不要单点谈判

**手上有两个 offer 再谈。** 只有一个的时候，你所有的"我再考虑一下"都是虚张声势，对方能听出来。

如果时间上凑不齐，可以**主动调节奏**：
- 快的那家问能不能宽限几天（"我还有一个流程在走，希望周五前给您答复"——**这句话本身就是筹码**，而且是诚实的）
- 慢的那家催一下（"我这边收到了一个 offer，需要在 X 号前答复，能否加快"）

这两句话都不算撒谎，也不失礼。

---

## 二、锚点：先想清楚三个数

| | 数字 | 说明 |
|---|---|---|
| **理想** | 20k | 谈判的开口价 |
| **目标** | 17k | 你真正想要的 |
| **底线** | 15k | 低于这个不接（除非有别的补偿） |

**先说区间还是先让对方说**：能让对方先说就让对方先说。被逼着先说时，**说区间而不是单点**，且把目标值放在区间下沿：「我期望 17 到 20k」——这样 17 是底，不是上限。

**不要说"都可以"、"看公司标准"**。10 年经验说这话，对方会直接按下限给。

---

## 三、薪资以外的六项，都要问清

工业岗位这几条对实际收入影响很大，**不问会吃亏**：

| 项 | 为什么重要 |
|---|---|
| **13 薪 / 14 薪 / 年终** | 15k×14 = 21万，17k×12 = 20.4万。**月薪低的那个反而更多** |
| **出差补贴** | 工业岗出差多。100/天和 300/天，一年差几万 |
| **加班与调休** | 现场调试经常通宵，有没有调休/加班费差别巨大 |
| **职级与调薪周期** | 一年一调还是两年一调？调幅大概多少？ |
| **社保公积金基数** | 按实发还是按最低基数？公积金比例？ |
| **试用期** | 时长、试用期薪资比例（有些给 80%） |

**把这些折算成年包再比较**，不要只比月薪。

---

## 四、谈判时怎么说

**给理由，不要只给数字。** 对方需要一个能向上汇报的依据：

> 我目前的期望是 17–20k。理由是我不是从零开始的转方向——10 年 C# 的工程能力可以直接用，同时这半年我把 Modbus、S7、OPC UA、MQTT 到时序库这条链路完整做了一遍，有可以演示的系统和压测数据。我进来之后不需要长时间的培养期，能直接接项目。

**如果对方压价**：

> 我理解预算有约束。如果 17k 确实有困难，能不能在**试用期长度**或**调薪周期**上做一些安排？比如三个月转正后按 17k 执行。

**这一招很有效**——它给了对方一个不突破当前预算就能成交的台阶，同时你拿到了书面承诺。

---

## 五、如果没达标

**按你自己写的后备路径走**，不要死磕：

> 若 6 个月未达标：先接 12–15k 的岗位，用 1 年真实项目经验再跳。
> 总耗时仍然远优于转 Java 或嵌入式。
> **不要因为差 2k 而继续待在原地。**

**这句话是你在计划开始时冷静写下的，现在的你要听那时的你的。** 人在焦虑或者不甘心的时候容易做出更差的决定。

**接了 12–15k 之后立刻定下一年目标**：
- 半年内独立负责一个完整项目
- 补上这半年没做扎实的部分（真实电磁环境、大规模部署、完整交付流程）
- **一年后带着真实项目经验再跳**，那时候的议价能力完全不同

## 七、无论结果如何，这半年你得到了什么

即使 offer 没到手，**这些是拿不走的**：

- 一套**能演示、能压测、有数字**的完整系统，和它的 GitHub 记录
- 从物理层到云平台的**完整链路认知**——这个视角很多做了十年的人也没有
- 6 篇技术博客（月度强制那一项）
- 一份**你自己验证过的**判断力：你评估了几个方向、选了复用率最高的那条、并且真的走完了

**M5 的项目和这条链路的认知，一年后依然有效。** 这不是白学的半年。
