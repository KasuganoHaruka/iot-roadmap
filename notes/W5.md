# W5 · 树莓派与 Linux 基本功

> 题库: Q31
> 术语: systemd unit, udev 规则, self-contained 发布

代码从你的开发机搬到一台**没有屏幕、断电会重启、你人不在现场**的机器上。这周学的全是"人不在现场时它还能自己活着"的手艺。

## 开始之前

**这周做什么** — 把程序搬到树莓派上，让它开机自启、崩了自己爬起来、串口名字不乱跑。

**读完你能** — 写一个 systemd unit；用 udev 固定设备名；用四条命令排查一个远程故障。

**需要什么** — 树莓派 + SD 卡，已装好 Ubuntu Server 并能 SSH。

**12 小时怎么分** — 系统安装与 SSH 2h · 发布部署 3h · systemd 2h · **udev 2h** · 排障命令练手 2h · Docker 1h

## 一、发布：self-contained 还是不是

```bash
dotnet publish -c Release -r linux-arm64 --self-contained \
  -p:PublishSingleFile=true -p:PublishTrimmed=true
```

| | self-contained | framework-dependent |
|---|---|---|
| 体积 | 60–80MB（裁剪后 30MB 左右） | 几 MB |
| 目标机要装 .NET | **不用** | 要装对应版本运行时 |
| 升级运行时 | 重新发布 | 改目标机 |

**现场选 self-contained。** 客户的树莓派上你没法保证有 .NET，也没法保证版本对。多出来的几十 MB 在 32G 的卡上不算什么。

> `PublishTrimmed` 会裁掉"看起来没被引用"的代码。**反射会被它坑**——如果你用了基于反射的 JSON 或 DI，先不裁剪，等跑通了再逐步开。

`RuntimeIdentifiers` 你的 `Iiot.EdgeGateway.csproj` 里已经写了 `linux-arm64;linux-x64;win-x64`。

## 二、systemd：开机自启、崩了自己爬起来

```ini
[Unit]
Description=IIoT Edge Gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
WorkingDirectory=/opt/iiot
ExecStart=/opt/iiot/Iiot.EdgeGateway
Restart=always
RestartSec=5
# 崩溃循环保护：10 分钟内重启超过 5 次就停下来，别把日志刷爆
StartLimitIntervalSec=600
StartLimitBurst=5
# 串口权限：要么加组，要么直接给设备权限
SupplementaryGroups=dialout
Environment=DOTNET_ENVIRONMENT=Production

[Install]
WantedBy=multi-user.target
```

几个必须理解的点：

- **`After=network-online.target` 不等于网络真的通了**。它只保证网络配置完成。MQTT 连不上仍要靠应用自己重试——**不要指望 systemd 帮你解决网络时序**。
- **`Restart=always` vs `on-failure`**：`always` 连正常退出也重启。守护进程用 `always`，一次性任务用 `on-failure`。
- **`Type=notify`** 需要你的程序主动告诉 systemd "我起来了"。.NET 用 `AddSystemd()`（`Microsoft.Extensions.Hosting.Systemd` 包）就能支持；不想装包就用 `Type=simple`。
- **崩溃循环保护是必须的**。没有它，一个启动就崩的 bug 会在一分钟内写几万行日志。

日志直接进 journald：

```bash
journalctl -u iiot-edge-gateway -f          # 实时跟
journalctl -u iiot-edge-gateway --since "1 hour ago"
journalctl -u iiot-edge-gateway -p err      # 只看错误
```

## 三、udev：让串口名字不再乱跑

**问题**：插两个 USB 转 485，一个是 `/dev/ttyUSB0` 一个是 `/dev/ttyUSB1`——**重启后可能对调**。你的点表配置就全错了，而且是"数据看着正常但对不上设备"的那种最难查的错。

**解法**：按硬件序列号固定名字。

```bash
# 先查出属性
udevadm info -a -n /dev/ttyUSB0 | grep -E 'idVendor|idProduct|serial'
```

```
# /etc/udev/rules.d/99-iiot-serial.rules
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6001", \
  ATTRS{serial}=="A50285BI", SYMLINK+="ttyModbus0", MODE="0660", GROUP="dialout"
```

```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
ls -l /dev/ttyModbus0     # → 指向 ttyUSB0 或 ttyUSB1，都无所谓了
```

**必须用 `serial` 而不是只用 vid/pid**：两个同型号的转换器 vid/pid 完全一样，只有序列号能区分。廉价的 CH340 有些**没有唯一序列号**——那就只能按 USB 物理端口路径（`KERNELS=="1-1.2"`）绑定，代价是换个插口就失效。

> 你仓库里 `deploy/99-iiot-serial.rules` 就是这个文件。

## 四、排障四件套（人不在现场时你只有这些）

```bash
ip a                          # 网卡起来没、IP 对不对
ss -tunlp                     # 谁在监听哪个端口（netstat 的替代）
journalctl -u <服务> -f       # 服务在说什么
tcpdump -i eth0 port 502 -nn -X   # 报文真的发出去了吗
```

**`tcpdump` 是终极裁判**。"我发了但对方没收到"和"我压根没发"，只有抓包能分清。常用：

```bash
tcpdump -i any port 1883 -nn          # MQTT
tcpdump -i eth0 host 192.168.1.10 -w cap.pcap   # 存下来拿回本地用 Wireshark 看
```

**现场没有网络怎么调试**（Q31 的答案）：
1. **日志分级 + 落盘**，运维能直接把文件拷走
2. 本地 HTTP 健康检查端点，手机连热点就能看（W8 会做）
3. **离线模拟器**：把现场设备的响应报文录下来，回办公室重放
4. 串口调试助手直接手发报文，绕过整个程序验证物理链路

## 五、Docker：这周只要跑通

M4 才真正用到，但环境要先备好：

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # 重新登录生效
docker run --rm hello-world
docker run -d -p 8080:80 nginx     # 验证端口映射
```

树莓派要注意**镜像架构**：`arm64` 和 `amd64` 的镜像不通用。多数官方镜像有多架构清单会自动选对，但小众镜像可能只有 amd64——`docker pull` 时会报 `no matching manifest`。
