## 一、先接线，再看软件

| 端子 | 接什么 | 常见错误 |
|---|---|---|
| L+ / M | 24V 电源正负 | 极性接反（多数 PLC 有防反接，但不要赌） |
| 1M / 2M | 输入公共端 | **漏接**——输入永远不动作，最常见的入门坑 |
| I0.0 ... | 数字输入（按钮） | 按钮另一端接 24V 还是 0V，取决于 PLC 是源型还是漏型 |
| Q0.0 ... | 数字输出（指示灯） | 输出公共端同样要接 |

**源型（PNP）/ 漏型（NPN）**：国产和西门子多为源型（输入端得到 +24V 视为 1），日系常见漏型。**接错了不会烧，但输入永远不动作**——这是你第一天最可能卡住的地方。

## 二、梯形图：五个指令就够看懂 80% 的程序

```
    I0.0     I0.1              Q0.0
 ───┤ ├──┬───┤/├───────────────( )───
          │
    Q0.0  │
 ───┤ ├───┘        ← 自锁（保持）
```

| 符号 | 名字 | 含义 |
|---|---|---|
| `┤ ├` | 常开触点 | 信号为 1 时导通 |
| `┤/├` | 常闭触点 | 信号为 **0** 时导通 |
| `( )` | 线圈 | 左边导通则置 1 |
| `TON` | 通电延时定时器 | 条件持续 N 秒后输出 |
| `CTU` | 加计数器 | 上升沿计数 |

**自锁**是上面那段的核心：按钮 `I0.0` 是点动的（松手就没了），靠 `Q0.0` 自己的常开触点并联把状态"锁住"，直到停止按钮 `I0.1`（常闭）断开。**这是所有启保停电路的基础**，看懂它就看懂了一半的现场程序。

**本周自己写的那个程序**：按钮启动 → 输出保持 → 停止复位 → `TON` 累计运行时长 → `CTU` 统计启动次数。运行时长和启动次数正好是你 M5 要采集的 OEE 基础数据。

**扫描周期**：PLC 是循环执行的——读输入 → 执行程序 → 写输出，周而复始，一轮通常 1–10ms。**这意味着 PLC 里一个持续时间小于扫描周期的脉冲，你可能采不到**。要采就得在 PLC 侧做锁存。

## 三、存储区：地址表示法必须搞清

| 区 | 含义 | 例子 |
|---|---|---|
| **I** | 输入映像区 | `I0.0`（第 0 字节第 0 位） |
| **Q** | 输出映像区 | `Q0.1` |
| **M** | 位存储区（中间变量） | `M10.0`、`MW20` |
| **DB** | 数据块（西门子特有，结构化数据） | `DB1.DBW4` |

**寻址后缀**决定读几个字节：

| 后缀 | 宽度 | 例子 | 占用 |
|---|---|---|---|
| `X` | 1 位 | `DB1.DBX0.0` | bit |
| `B` | 1 字节 | `DB1.DBB2` | 1 |
| `W` | 2 字节 | `DB1.DBW2` | 2 |
| `D` | 4 字节 | `DB1.DBD4` | 4 |

**手算地址是 W10 的必备技能**。一个 DB 块里依次放 `Bool, Int, Real`：

```
DB1.DBX0.0   Bool    偏移 0.0
             ← 布尔占 1 位，但下一个 Int 要按 2 字节对齐，所以跳到 2
DB1.DBW2     Int     偏移 2
DB1.DBD4     Real    偏移 4
```

**对齐规则**：Int 按 2 字节对齐，Real/DInt 按 4 字节对齐。**算错一个字节，后面全错位**——这是 W10 最容易卡住的地方。

## 四、PLC 是大端，x86 是小端（牢记）

西门子、三菱、大多数 PLC 内部都是**大端**（高字节在低地址）。你的 C# 跑在 x86/ARM 上是**小端**。

```csharp
// 从 PLC 读回 4 字节 [0x41, 0x20, 0x00, 0x00]，这是大端的 float 10.0
var bytes = new byte[] { 0x41, 0x20, 0x00, 0x00 };
if (BitConverter.IsLittleEndian) Array.Reverse(bytes);
var value = BitConverter.ToSingle(bytes);   // 10.0f
```

或者直接用 .NET 的显式端序 API，比手动 Reverse 清楚：

```csharp
var value = BinaryPrimitives.ReadSingleBigEndian(bytes);
```

**这和 W3 的字序是同一类问题的两个层面**：Modbus 的字序是"两个寄存器谁在前"（协议层的非标），PLC 的大端是"一个整数内部字节顺序"（体系结构层的标准）。**面试时能把这两件事分清，是加分的**。

## 五、客户不让改 PLC 程序，怎么采数（Q29）

现场极常见——PLC 程序动一下要重新验证整条产线，客户不会答应。

**按优先级排的方案**：

1. **只读现有地址**。PLC 里的数据本来就在 DB/M 区，读走不影响程序运行。**这是首选，而且完全不需要动程序。**
2. **用 PLC 已经开放的通信口**。多数 PLC 出厂就支持 Modbus TCP 从站或 S7 通信，不需要改梯形图，只要在通信配置里勾一下。
3. **加一个只读的通信 DB**。如果非要新增，申请加一个**只被读、不被程序引用**的 DB 块——风险最低，容易通过评审。
4. **旁路采集**。实在不让碰 PLC，就在电气柜里并联信号：电流互感器、脉冲输出、干接点。数据质量差一些，但完全不侵入。
5. **最后手段：读 HMI 的通信**。有些现场只有触摸屏能连 PLC，可以抓 HMI 与 PLC 之间的报文。

> 面试话术："我优先只读，不申请写权限；确实要新增就申请一个不被程序逻辑引用的只读 DB，评审时的说服点是'不改变任何既有扫描逻辑'。实在不批就走旁路。"
